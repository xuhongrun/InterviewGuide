# 传感器接入实战

> 机器人常用传感器：相机、深度相机、激光雷达、IMU、GNSS-RTK、里程计、F/T 力觉、超声/红外。重点：驱动选择、外参标定、时间同步、ROS 话题对齐。

---

## 一、相机（RGB / 双目 / 鱼眼）

### 1.1 接入

| 接口 | 驱动 |
|------|------|
| USB UVC | `v4l2_camera` / `usb_cam` |
| GigE Vision | `aravis_camera_driver` / `pylon_ros2_camera` (Basler) |
| MIPI-CSI（Jetson） | `argus_camera`、`isaac_ros_argus_camera` |
| GMSL（Drive Orin / 自动驾驶） | `nvidia-isaac-ros-image-pipeline` |

发布话题：
- `image_raw` (sensor_msgs/Image) + `camera_info` (CameraInfo)；
- 经 `image_proc` → `image_rect`（去畸变）；
- `image_transport` 提供 `raw / compressed / theora / h264`。

### 1.2 标定

```bash
ros2 run camera_calibration cameracalibrator \
    --size 8x6 --square 0.025 \
    --ros-args -r image:=/camera/image_raw -r camera:=/camera
```

输出 `camera_info.yaml`，内含 `K, D, R, P`：
- K：3×3 内参；
- D：畸变（plumb_bob/equidistant）；
- R：双目立体校正旋转；
- P：3×4 投影矩阵（双目时含基线）。

### 1.3 双目深度

`stereo_image_proc`：
```bash
ros2 launch stereo_image_proc stereo_image_proc.launch.py
```

输出 `disparity` + `points2`。

## 二、深度相机

### 2.1 RealSense (Intel)

```bash
sudo apt install ros-jazzy-realsense2-camera
ros2 launch realsense2_camera rs_launch.py \
    enable_color:=true enable_depth:=true enable_infra1:=true \
    align_depth.enable:=true pointcloud.enable:=true
```

发布：
- `/camera/color/image_raw`
- `/camera/aligned_depth_to_color/image_raw`
- `/camera/depth/color/points`
- `/camera/imu`（D435i / D455）

注意：USB3 + 主动散热，否则掉帧。

### 2.2 Azure Kinect / Orbbec

`Azure_Kinect_ROS_Driver` / `OrbbecSDK_ROS2`，注意时间戳源（hardware vs ROS）。

### 2.3 ToF / 结构光通用要点

- 深度对齐到彩色（align_depth）；
- 滤波：spatial / temporal / hole_filling；
- 远距噪声大，工作距离限制。

## 三、激光雷达

### 3.1 2D LiDAR

| 厂商 | 驱动 |
|------|------|
| RPLIDAR | `rplidar_ros2` |
| Hokuyo | `urg_node2` |
| SICK | `sick_scan_xd` |

发布 `sensor_msgs/LaserScan`。

### 3.2 3D LiDAR

| 厂商 | 驱动 |
|------|------|
| Velodyne (VLP-16/32) | `velodyne` |
| Ouster | `ouster-ros` |
| Hesai (Pandar 系列) | `HesaiLidar_General_ROS_2.0` |
| Livox | `livox_ros_driver2` |
| RoboSense | `rslidar_sdk` |

发布：`sensor_msgs/PointCloud2` + 厂商可能附 IMU、ring/azimuth 字段。

### 3.3 重要参数

- `frame_id`、`min_range`、`max_range`、`organize`（结构化 vs 散）；
- 多回波（first/last/strongest）；
- 时间戳模式：**每点时戳 vs 帧时戳** —— SLAM 必须用每点时戳并做去畸变（运动补偿）。

### 3.4 标定

LiDAR-IMU、LiDAR-Camera：
- `kalibr_calibration` (cam-imu)
- `direct_visual_lidar_calibration`
- `lidar_align`、`lidar_camera_calibration`
- 自动驾驶常用棋盘 / 标定板 / 自然场景。

## 四、IMU

| 类型 | 示例 |
|------|------|
| MEMS（消费） | MPU-6050 / BMI088（D435i 内置） |
| 工业 IMU | Xsens Mti、Microstrain 3DM、Epson G370 |
| 光纤陀螺 | KVH、iXblue |
| 惯导 / GNSS-INS | Novatel SPAN, OxTS |

驱动：`xsens_mti_ros2_driver`、`microstrain_inertial_driver`、`bno055`。

发布 `sensor_msgs/Imu`：
- `linear_acceleration`（加速度，单位 m/s²，**含重力**）；
- `angular_velocity`（角速度 rad/s）；
- `orientation`（部分 IMU 提供四元数姿态）；
- 协方差矩阵填齐。

标定：
- 内参：`imu_utils`、`allan_variance_ros` 估计噪声谱；
- 外参（IMU-Cam / IMU-LiDAR）：`kalibr`。

## 五、GNSS / RTK

驱动：
- `ublox_dgnss`（u-blox F9P/X20P）
- `septentrio_gnss_driver`
- `nmea_navsat_driver`（通用 NMEA）

话题：
- `sensor_msgs/NavSatFix`：经纬高 + 协方差 + 状态；
- `sensor_msgs/NavSatStatus`：固定/差分/RTK fixed/float；
- 速度 / 朝向（双天线）走 `geometry_msgs/TwistWithCovarianceStamped` + `Heading`。

RTK 接入 NTRIP：`ntrip_client` 节点订阅 GGA、转发 RTCM3 给基站。

## 六、里程计（轮式 / 视觉 / 惯导）

| 类型 | 来源 |
|------|------|
| 轮式 | 编码器 → diff_drive_controller / Ackermann |
| 视觉 | ORB-SLAM / VINS-Fusion / OpenVSLAM |
| LIO | Fast-LIO / LIO-SAM |
| GNSS-INS | 高级惯导一体机 |

发布 `nav_msgs/Odometry`：含 pose + twist + 协方差 + 子帧。

融合：`robot_localization` (`ekf_node` / `ukf_node`)：
```yaml
ekf_filter_node:
  ros__parameters:
    frequency: 50.0
    two_d_mode: true
    odom0: /wheel/odom
    odom0_config: [false,false,false, false,false,false, true,true,false, false,false,true, false,false,false]
    imu0: /imu/data
    imu0_config:  [false,false,false, true,true,false, false,false,false, true,true,true, true,true,false]
```

## 八、时间同步

| 方法 | 精度 |
|------|------|
| `chrony` NTP | ~ms |
| **PTP (1588)** | μs（推荐工业用） |
| **PPS + GPS** | ns |
| 硬件触发同步 | ns（相机/LiDAR 共触发） |

驱动应支持外触发、PTP、PPS：
- 设置正确的 `time_source` 参数；
- 时间戳来自硬件（header.stamp = sensor 时间），而非接收时刻。

## 九、`message_filters` 多源同步

```cpp
message_filters::Subscriber<Image> img_sub(node, "image");
message_filters::Subscriber<CameraInfo> info_sub(node, "camera_info");
typedef sync_policies::ApproximateTime<Image, CameraInfo> Sync;
Synchronizer<Sync> sync(Sync(10), img_sub, info_sub);
sync.registerCallback(std::bind(&Cls::cb, this, _1, _2));
```

`ExactTime` vs `ApproximateTime`：硬件同步用前者，软件同步用后者。

## 十、常见坑

| 现象 | 排查 |
|------|------|
| 相机帧率掉 | USB 带宽 / 散热 / 驱动 |
| 点云抖 | 时间戳不准 / 没运动补偿 |
| IMU 偏置漂 | 静止初始化时间不足；做 Allan 标定 |
| RTK 不固定 | 基线、星历、遮挡；NTRIP 不通 |
| robot_localization 漂 | 协方差填错；odom0_config 矩阵不对 |
| 多源同步失败 | QoS 不一致 / `ApproximateTime` slop 太小 |

## 十一、面试速记

- 相机 / LiDAR 标定走 **camera_calibration**、**kalibr**；外参 LiDAR-Cam 用 **direct_visual_lidar_calibration**
- IMU 数据 **含重力**；噪声谱 **allan_variance_ros**
- 点云 SLAM 必须做 **运动补偿**，需每点时戳
- RTK 进阶：**NTRIP + RTCM3**，状态 `STATUS_GBAS_FIX`(=2 RTK)
- 多源融合：**`robot_localization` 的 EKF/UKF**，配置矩阵控制启用维度
- 时间同步：消费级 chrony，工业 **PTP**，最高精度硬件触发
- 多传感器对齐：`message_filters::ApproximateTime` 或 ExactTime

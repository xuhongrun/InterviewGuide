## C++ 进程间通信（IPC）

> 1. 管道（Pipe）：管道是半双工的，数据只能单向流动；而且只能在具有亲缘关系的进程间使用（例如父子进程）。
> 2. 命名管道（Named Pipe）：命名管道允许无亲缘关系的进程间通信。
> 3. 共享内存（Shared Memory）：共享内存允许多个进程访问同一块内存空间，是最快的IPC方式。但需要配合信号量等同步机制来避免冲突。
> 4. 消息队列（Message Queue）：消息队列是消息的链表，存放在内核中并由消息队列标识符标识。克服了信号传递信息少、管道只能承载无格式字节流等缺点。
> 5. 套接字（Socket）：可用于不同机器间的进程通信，也可用于同一台机器上的进程通信。

---

### **1. 管道（Pipe）**
**特点**：
- 半双工通信（单向）
- 仅适用于父子进程或兄弟进程
- 基于字节流，无消息边界
- 随进程结束自动销毁

**原型**：
```cpp
#include <unistd.h>
int pipe(int fd[2]);  // fd[0]:读端, fd[1]:写端
```

**使用场景**：
- Shell 命令中的 `|` 操作符
- 父子进程间简单数据传递

**实现机制**：
- 内核创建环形缓冲区（默认64KB）
- 通过文件描述符读写

**注意点**：
- 写端关闭后读端返回EOF
- 读端关闭后写端触发`SIGPIPE`
- 需手动关闭未使用的文件描述符

---

### **2. 命名管道（FIFO）**
**特点**：
- 有文件系统路径名
- 支持无亲缘关系进程
- 先进先出（FIFO）队列

**原型**：
```cpp
#include <sys/stat.h>
int mkfifo(const char *path, mode_t mode);
```

**使用场景**：
- 不同进程的持久化通信
- 日志收集系统

**实现机制**：
- 通过文件路径标识
- 内核管理内存缓冲区

**注意点**：
- 打开时可能阻塞（需两端同时打开）
- 需处理文件权限问题
- 数据原子性（Linux限定4096字节）

---

### **3. 消息队列**
**特点**：
- 全双工通信
- 消息类型过滤
- 内核持久化（显式删除）

**原型**：
```cpp
#include <sys/msg.h>
int msgget(key_t key, int flag);       // 创建/获取
int msgsnd(int id, const void *msg, size_t size, int flag);  // 发送
ssize_t msgrcv(int id, void *msg, size_t size, long type, int flag); // 接收
```

**使用场景**：
- 优先级消息传递
- 异步任务分发

**实现机制**：
- 内核维护消息链表
- 消息结构：`long mtype + char mtext[]`

**注意点**：
- 消息最大长度受限（`/proc/sys/kernel/msgmax`）
- 队列数量限制（`msgmni`）
- 需手动删除（`msgctl(, IPC_RMID)`）

---

### **4. 共享内存**
**特点**：
- 速度最快的IPC
- 无内核复制开销
- 需同步机制配合

**原型**：
```cpp
#include <sys/shm.h>
int shmget(key_t key, size_t size, int flag);  // 创建
void *shmat(int id, const void *addr, int flag);  // 挂载
int shmdt(const void *addr);  // 卸载
```

**使用场景**：
- 大数据交换（如图像处理）
- 实时数据库访问

**实现机制**：
- 映射相同物理内存页
- 通过虚拟地址访问

**注意点**：
- 必须使用信号量/互斥锁同步
- 需处理指针有效性
- 手动清理（`shmctl(, IPC_RMID)`）

---

### **5. 信号量（Semaphore）**
**特点**：
- 进程同步原语
- 计数器实现互斥
- 支持原子操作

**原型**：
```cpp
#include <sys/sem.h>
int semget(key_t key, int nsems, int flag);  // 创建
int semop(int id, struct sembuf *ops, size_t nops);  // 操作
```

**使用场景**：
- 共享资源互斥访问
- 生产者-消费者模型

**实现机制**：
- 内核维护计数器
- P操作（-1阻塞）/V操作（+1唤醒）

**注意点**：
- 需初始化值（`semctl(SETVAL)`）
- 防止死锁
- 系统级资源限制

---

### **6. 信号（Signal）**
**特点**：
- 异步事件通知
- 预定义信号类型有限
- 不能传递数据

**原型**：
```cpp
#include <signal.h>
int kill(pid_t pid, int sig);  // 发送
sighandler_t signal(int sig, sighandler_t handler);  // 处理
```

**使用场景**：
- 进程终止通知
- 紧急事件处理

**实现机制**：
- 内核中断目标进程
- 执行注册的信号处理函数

**注意点**：
- 处理函数需异步安全
- 信号可能丢失
- 不能用于常规数据传递

---

### **7. 套接字（Socket）**
**特点**：
- 支持网络通信
- 全双工字节流
- 跨平台兼容性好

**原型**：
```cpp
#include <sys/socket.h>
int socket(int domain, int type, int protocol);  // 创建
bind(); listen(); accept();  // 服务端
connect();  // 客户端
```

**使用场景**：
- 分布式系统通信
- 跨主机进程交互

**实现机制**：
- TCP/UDP协议栈
- 内核网络缓冲区

**注意点**：
- 需处理序列化/反序列化
- 注意连接状态管理
- 存在网络延迟

---

### IPC方式对比

| 通信方式      | 通信方向 | 亲缘要求 | 数据形式      | 速度   | 同步需求       | 持久性       | 复杂度 |
|---------------|----------|----------|---------------|--------|----------------|--------------|--------|
| **管道**      | 单向     | 父子进程 | 字节流        | 中     | 自动阻塞       | 进程结束销毁 | ★★☆    |
| **命名管道**  | 单向     | 无       | 字节流        | 中     | 需两端打开     | 手动删除     | ★★★    |
| **消息队列**  | 双向     | 无       | 结构化消息    | 中     | 消息级阻塞     | 显式删除     | ★★★☆   |
| **共享内存**  | 双向     | 无       | 原始字节      | 极高   | 需额外同步     | 显式删除     | ★★★★   |
| **信号量**    | N/A      | 无       | 同步计数器    | 高     | 原子操作       | 显式删除     | ★★★☆   |
| **信号**      | 单向     | PID可见  | 信号编号      | 高     | 异步           | 瞬时         | ★★☆    |
| **套接字**    | 全双工   | 无       | 字节流/数据报 | 低-中  | 连接级管理     | 显式关闭     | ★★★★☆  |


| 机制            | 传输方式          | 适用场景                  | 优点                          | 缺点                          |
|-----------------|-------------------|--------------------------|-------------------------------|-------------------------------|
| **共享内存**    | 内存直接访问      | 高性能数据共享           | 最快速度（无需拷贝）          | 需要同步机制                  |
| **管道**        | 字节流            | 父子进程简单通信         | 简单易用                      | 单向通信，容量有限            |
| **消息队列**    | 结构化消息        | 异步通信                 | 支持消息类型，可非阻塞        | 系统级限制（队列数量/大小）   |
| **信号量**      | 计数器            | 同步控制                 | 精确控制资源访问              | 仅用于同步，不传输数据        |
| **Socket**      | 网络协议          | 跨网络/跨主机            | 最通用，支持异构系统          | 性能开销最大                  |
| **信号**        | 预定义事件        | 紧急通知                 | 即时响应                      | 信息量有限（仅信号编号）      |

---

### 选择建议：
1. **高性能场景**：共享内存 + 信号量
2. **结构化消息**：消息队列
3. **简单父子进程**：管道
4. **跨网络通信**：套接字
5. **紧急事件**：信号

> 注意：所有System V IPC需用`ipcs`/`ipcrm`管理，避免资源泄漏。Windows平台替代方案：共享内存(`CreateFileMapping`)、命名管道(`CreateNamedPipe`)。

# 网络 最佳实践

> 涵盖客户端、服务端、协议选择、连接管理、可靠性、安全、可观测性。

---

## 1. 协议选型

| 场景 | 协议 |
|------|------|
| Web / API | **HTTP/2 或 HTTP/3 + JSON / Protobuf** |
| 内部 RPC（低延迟） | **gRPC**（HTTP/2 + Protobuf） / Thrift |
| 实时双向 | **WebSocket** / gRPC streaming / SSE（单向） |
| 高吞吐流 | **Kafka / Pulsar** |
| 任务队列 | **RabbitMQ / Redis Streams / NATS JetStream** |
| 物联网弱网 | **MQTT** / CoAP |
| 机器人 / 实时 | **DDS / Zenoh / SOME/IP** |
| 同主机 IPC | **Unix Domain Socket / 共享内存 / gRPC over UDS** |

---

## 2. 客户端

* **永远开连接池**：HTTP keep-alive + 连接复用，避免每请求 3-RTT 握手。
* **超时三件套**：connect、read、total；不设置 = 永久挂死。
* **重试**：仅幂等请求；指数退避 + jitter；最多 3~5 次；遇 4xx **不要重试**。
* **熔断**：连续失败 N 次或 P95 异常时半开探测（Hystrix / resilience4j / sentinel）。
* **限流（客户端侧）**：令牌桶 / 漏桶；接收 429 时按 `Retry-After` 后退。
* **DNS 缓存**：JVM 默认无限缓存（坑），设置 `-Dnetworkaddress.cache.ttl=30`；使用 SRV 记录或服务发现。

```python
import httpx, tenacity
@tenacity.retry(
    stop=tenacity.stop_after_attempt(3),
    wait=tenacity.wait_exponential_jitter(initial=0.1, max=2),
    retry=tenacity.retry_if_exception_type(httpx.TransportError),
)
def get(client, url): return client.get(url, timeout=2.0).raise_for_status()
```

## 3. 服务端

* **优雅启停**：监听 SIGTERM → 停接受新连接 → 等待 in-flight 完成 → 退出。
* **连接限额**：`backlog` 合理（512~4096）；max_connections 防 fd 耗尽。
* **请求超时与队列上限**：避免慢请求堆积导致雪崩。
* **健康检查分离**：`/healthz`（liveness，进程是否活）vs `/readyz`（readiness，是否可接流量）；K8s 用 readiness 决策。
* **异步与背压**：上游慢时主动拒绝（429 / 503），不要无限缓冲。
* **零拷贝**：静态文件 `sendfile`；mmap；TLS 场景用 `kTLS`。
* **CPU 亲和**：网络密集服务 pin 到 NUMA 同节点核 + RPS / RFS / IRQ 均衡。

## 4. TCP 调优（Linux）

```bash
# /etc/sysctl.d/99-net.conf
net.core.somaxconn = 4096
net.core.netdev_max_backlog = 5000
net.core.rmem_max = 16777216
net.core.wmem_max = 16777216
net.ipv4.tcp_rmem = 4096 87380 16777216
net.ipv4.tcp_wmem = 4096 65536 16777216

net.ipv4.tcp_tw_reuse = 1          # 复用 TIME_WAIT
net.ipv4.tcp_fin_timeout = 15
net.ipv4.tcp_max_syn_backlog = 8192
net.ipv4.tcp_syncookies = 1        # SYN flood 防御
net.ipv4.tcp_mtu_probing = 1       # 自动探测 MTU

net.ipv4.tcp_congestion_control = bbr   # 长肥管道更优
net.core.default_qdisc = fq
```

* **不要随便改 `tcp_tw_recycle`**（已在 4.12 移除）。
* 长连接默认开 `TCP_NODELAY`，吞吐型加 `TCP_CORK` / `TCP_NOTSENT_LOWAT`。
* 短连接 + 高并发 → 走连接池而非反复 TIME_WAIT。

## 5. 安全基线

| 项 | 做法 |
|------|------|
| **传输** | 全站 TLS 1.2/1.3，禁用 SSLv3/TLS 1.0/1.1；HSTS + preload |
| **证书** | Let's Encrypt + ACME 自动续期；监控到期；移动端考虑 Pinning |
| **认证** | OAuth2 / OIDC；JWT 签名 + 短 TTL + Refresh；不要把权限只放前端 |
| **授权** | 每请求验证 RBAC / ABAC；最小权限 |
| **输入** | 全部校验 + 强类型；防 SSRF（出站白名单） |
| **限流** | 网关层（Envoy / Nginx / APISIX）+ 应用层双重 |
| **DDoS** | CDN + WAF；SYN cookie；连接数上限 |
| **日志** | 不记录敏感信息（token / pwd / 身份证）；脱敏 |
| **依赖** | Snyk / Dependabot 监测 CVE |

## 6. 长连接管理

* **应用层心跳**比 `SO_KEEPALIVE` 更可靠（默认 2h 太长）；推荐 30~60s 一次。
* **NAT / LB 超时**：典型 300s 空闲断开；心跳间隔 < 该值。
* **WebSocket / gRPC**：定期 ping/pong；服务端配 `MAX_CONNECTION_IDLE` 主动回收。
* 客户端断线**指数退避重连** + **jitter** 避免重连风暴。

---

## 7. 服务发现与负载均衡

* **客户端发现**：服务注册到 Consul / etcd / Nacos / Eureka；客户端拉取 + 本地负载。
* **服务端发现**：DNS / VIP + L4 LB（HAProxy / IPVS / AWS NLB）/ L7 LB（Envoy / Nginx）。
* **网格 Service Mesh**：Istio / Linkerd 把流量管控放 sidecar。
* **算法**：Round Robin / Least Conn / EWMA（推荐，对长尾敏感）/ Consistent Hash（缓存）。
* **优雅摘除**：先 readiness=false → 等流量止 → 关闭。

## 8. 可观测性 RED / USE

* **RED**：Rate / Errors / Duration（请求维度）。
* **USE**：Utilization / Saturation / Errors（资源维度）。
* **三大支柱**：Logs（结构化 JSON）+ Metrics（Prometheus）+ Traces（OpenTelemetry）。
* 必备指标：
  * QPS、P50/P95/P99 延迟、错误率（按状态码分桶）
  * 活跃连接数、accept 队列长度、TIME_WAIT 数
  * 网卡 PPS、bps、retrans 率（`ss -i`）
  * 上游依赖延迟（按下游服务/host 切片）
* **trace 透传**：W3C Trace Context (`traceparent`)、B3 Header；跨语言一致。

* 模拟劣质网络是常态：100ms ± 30ms 延迟、1% 丢包、5Mbps 限速。

## 10. 反模式 Top 12

1. 不设超时 / 永久挂死。
2. 重试不加幂等性判断 → 副作用倍增。
3. 客户端无连接池 → CPU 全花在握手。
4. 服务端 backlog 太小，accept 队列溢出但无监控。
5. 用 `gethostbyname` / 阻塞 DNS。
6. JWT 永不过期、永不轮换密钥。
7. 全站 HTTP 明文，或开启 `verify=False` 跳证书校验。
8. 把所有错误统一返回 200，让客户端解析 body 判断。
9. 心跳 = TCP keepalive（默认 2h，业务早挂了）。
10. 优雅关闭只发 SIGKILL。
11. 调度器不开 readiness probe，发布即抖动。
12. 监控只看 P50（长尾被忽略）。

## 11. Top 20 Checklist

1. ☐ 全链路设置 connect/read/total 超时。
2. ☐ 客户端连接池 + 重试 + 退避 + 熔断。
3. ☐ 服务端 backlog ≥ 1024，监控 accept 队列。
4. ☐ TLS 1.2/1.3 强制，HSTS preload。
5. ☐ 证书自动续期 + 到期告警。
6. ☐ 应用层心跳 30~60s。
7. ☐ readiness vs liveness 分离。
8. ☐ 优雅关闭：SIGTERM → drain → exit。
9. ☐ TCP 内核参数调优（somaxconn / rmem / BBR）。
10. ☐ HTTP keep-alive + HTTP/2 启用。
11. ☐ 限流分网关层 + 应用层。
12. ☐ DDoS：CDN + WAF + SYN cookie。
13. ☐ 出站请求白名单防 SSRF。
14. ☐ 日志脱敏，无密钥/token。
15. ☐ 三大可观测性 + RED/USE 仪表盘。
16. ☐ trace 跨服务透传。
17. ☐ 故障演练：丢包/延迟/上游挂。
18. ☐ 压测覆盖正常 + 峰值 + 劣质网络。
19. ☐ 服务发现 + 优雅摘除。
20. ☐ 依赖 CVE 自动扫描。

## 面试速记

1. **超时永远要有**：connect / read / total。
2. **重试 = 退避 + jitter + 幂等**，否则放大故障。
3. **熔断 + 限流 + 降级** 三件套防雪崩。
4. **HTTP keep-alive + 连接池** 是性能基础。
5. **BBR + fq** 拥塞控制更适合长肥管道。
6. **TLS 1.3** 1-RTT，0-RTT 防重放只用幂等 GET。
7. **优雅关闭**：先 readiness=false，等 in-flight 退出。
8. **粘包**：TCP 是字节流，应用层 framing 必备。
9. **可观测性三件套**：metrics + logs + traces。
10. **故障演练常态化**：tc/netem/toxiproxy/chaos mesh。

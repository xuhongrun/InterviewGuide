## 1. SQL 基础

### 1.1 DDL / DML / DCL / TCL

| 类别 | 命令 |
|------|------|
| DDL（结构） | `CREATE` / `ALTER` / `DROP` / `TRUNCATE` |
| DML（数据） | `SELECT` / `INSERT` / `UPDATE` / `DELETE` |
| DCL（权限） | `GRANT` / `REVOKE` |
| TCL（事务） | `BEGIN` / `COMMIT` / `ROLLBACK` / `SAVEPOINT` |

### 1.2 JOIN

```sql
-- INNER：两表都有
SELECT u.name, o.id FROM users u INNER JOIN orders o ON o.uid = u.id;
-- LEFT：左表全保留，右表无匹配补 NULL
-- RIGHT / FULL OUTER：类似
-- CROSS：笛卡尔积
-- SELF JOIN：表自连接（员工-上级）
```

### 1.3 聚合 + 分组

```sql
SELECT category, COUNT(*) AS n, AVG(price) AS avg_p
FROM products
WHERE stock > 0
GROUP BY category
HAVING n > 10
ORDER BY avg_p DESC
LIMIT 20;
```

执行顺序：`FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT`。

### 1.4 子查询 / CTE / 窗口函数

```sql
WITH ranked AS (
  SELECT id, dept, salary,
         RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS r
  FROM employee
)
SELECT * FROM ranked WHERE r <= 3;   -- 每部门 top 3
```

窗口函数：`ROW_NUMBER` / `RANK` / `DENSE_RANK` / `LAG` / `LEAD` / `SUM() OVER(...)`.

## 2. 索引

### 2.1 索引类型

| 类型 | 适用 |
|------|------|
| **B+ 树** | 范围 + 等值，MySQL InnoDB 默认 |
| **Hash** | 等值快，不能范围；Memory 引擎 / Redis 字典 |
| **倒排索引** | 全文检索（ES、Lucene） |
| **位图 Bitmap** | 低基数列、OLAP（Druid、ClickHouse） |
| **空间 R-Tree** | 地理位置 / GIS |
| **GiST / GIN** | PostgreSQL 通用 / 全文 / JSON |

### 2.2 InnoDB 索引

* **聚簇索引**：主键 → 数据行（叶子是数据本身）。
* **二级索引**：叶子存主键 → **回表**取数据。
* **覆盖索引**：查询列全在索引上 → 不回表。
* **联合索引最左前缀**：`(a,b,c)` 命中 `a`、`a,b`、`a,b,c`，不命中 `b` 单查。
* **索引下推 ICP**：5.6+ 在存储引擎层先过滤非索引列条件，减少回表。

### 2.3 索引失效场景

```sql
-- 1. 列上函数 / 表达式
WHERE YEAR(created_at) = 2025          -- ❌
WHERE created_at >= '2025-01-01'        -- ✅

-- 2. 隐式类型转换
WHERE phone = 13800001234               -- phone 是 varchar → ❌
WHERE phone = '13800001234'             -- ✅

-- 3. 前导通配符 LIKE
WHERE name LIKE '%abc'                  -- ❌
WHERE name LIKE 'abc%'                  -- ✅

-- 4. OR 涉及非索引列、IS NULL（部分版本）
-- 5. 联合索引违反最左前缀
-- 6. 优化器估算认为全表更快
```

### 2.4 索引设计原则

* 高频 WHERE / JOIN / ORDER BY / GROUP BY 列建索引。
* **选择性**（distinct/total）高的列优先（如用户ID > 性别）。
* 联合索引把高选择性列放左。
* 不要每列都建索引：写性能 ↓，存储 ↑。
* 长字符串用前缀索引：`KEY(name(20))`。
* `EXPLAIN` 看执行计划：type、key、rows、Extra（Using index / Using filesort / Using temporary）。

## 3. 事务与隔离

### 3.1 ACID

* **A**tomicity 原子性：要么全成要么全败（undo log）。
* **C**onsistency 一致性：约束不被破坏。
* **I**solation 隔离性：并发互不干扰（MVCC + 锁）。
* **D**urability 持久性：提交后断电不丢（redo log + WAL）。

### 3.2 隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|------|------------|------|
| Read Uncommitted | ✅ | ✅ | ✅ |
| Read Committed (Oracle / PG 默认) | ❌ | ✅ | ✅ |
| Repeatable Read (MySQL InnoDB 默认) | ❌ | ❌ | ⚠️ MVCC + 间隙锁可避免 |
| Serializable | ❌ | ❌ | ❌ |

* **脏读**：读到未提交的数据。
* **不可重复读**：两次读同一行结果不同（其他事务修改并提交）。
* **幻读**：两次范围查询结果集不同（其他事务插入）。

### 3.3 MVCC（多版本并发控制）

* InnoDB 每行存 `trx_id` + 回滚指针 → 多版本链。
* 一致性读：根据 ReadView 判断哪个版本可见。
* RR 在事务首次 SELECT 创建 ReadView；RC 每次 SELECT 创建。
* 解决"读不阻塞写、写不阻塞读"。

### 3.4 锁

* **行锁**（Record Lock） / **间隙锁**（Gap） / **临键锁**（Next-Key = 行 + 前间隙）。
* **意向锁**（IS / IX）：表级锁与行级锁兼容。
* **共享锁 S** / **排他锁 X**。
* **死锁**：事务循环等待 → InnoDB 自动检测并 rollback 一个；或超时 `innodb_lock_wait_timeout`。

## 5. NoSQL 全景

| 类型 | 代表 | 适用 |
|------|------|------|
| **K-V** | Redis / Memcached | 缓存、计数、Session |
| **文档** | MongoDB / Couchbase | Schema 灵活、JSON 业务 |
| **列族** | HBase / Cassandra / ScyllaDB | 海量写、宽表、时序 |
| **图** | Neo4j / NebulaGraph / JanusGraph | 关系网络、推荐 |
| **时序** | InfluxDB / TimescaleDB / VictoriaMetrics | 监控、IoT |
| **搜索** | Elasticsearch / OpenSearch | 全文、日志 |

### Redis 必懂

* **5 + N 数据结构**：String / List / Hash / Set / ZSet / Stream / HyperLogLog / Bitmap / GEO。
* **持久化**：RDB（快照） + AOF（追加日志，appendfsync everysec 推荐）。
* **集群**：主从 + 哨兵 / Cluster（16384 槽 / CRC16）。
* **缓存三大问题**：
  * **穿透**：查不存在的 key → 布隆过滤器 / 空值缓存。
  * **击穿**：热点 key 失效瞬间打 DB → 互斥锁 / 永不过期。
  * **雪崩**：大量 key 同时失效 → 随机过期 + 多级缓存。
* **缓存一致性**：Cache-Aside（更新 DB → 删缓存，配合延迟双删）；不要"先删后写"。

## 6. 高级话题

### 6.1 分库分表

* **垂直分库**：按业务（订单库 / 用户库）。
* **垂直分表**：宽表拆窄（冷热分离）。
* **水平分表**：按 ID 哈希 / 范围 / 一致性哈希。
* **挑战**：跨库 JOIN、分布式事务、全局 ID（雪花 Snowflake）、分页（深分页改 search_after）。
* **中间件**：Vitess、ShardingSphere、MyCAT、TiDB（原生分布式）。

### 6.2 读写分离

主写 + 从读；从延迟问题 → 强一致读走主，或半同步。

### 6.3 分布式 ID

* UUID：无序，索引差。
* **Snowflake**：64 位 = 1 + 41 时间戳 + 10 机器 + 12 序列；时钟回拨需处理。
* DB 号段：批量取一段 ID 缓存。
* Redis INCR。

### 6.4 慢查询排查

1. `slow_query_log` 打开，阈值 1s。
2. `pt-query-digest` / `mysqldumpslow` 聚合。
3. `EXPLAIN` 看执行计划，`SHOW PROFILE` 看耗时。
4. 常见原因：缺索引、回表多、临时表 / filesort、JOIN 顺序差、统计信息过旧（`ANALYZE TABLE`）。

### 6.5 死锁排查

`SHOW ENGINE INNODB STATUS\G` → LATEST DETECTED DEADLOCK 段；按事务持有锁 / 等待锁分析顺序。

### 6.6 分布式事务

详见 [分布式系统](../architecture/分布式系统.md) / [微服务架构](../architecture/微服务架构.md)。
2PC / 3PC / TCC / Saga / Outbox。

## 8. Top 20 数据库 Checklist

1. ☐ 主键必有；优先单调递增（自增 / 雪花）减少页分裂。
2. ☐ 关键查询走索引，`EXPLAIN` 验证 + 周期 review 慢查询。
3. ☐ 联合索引按选择性 / 高频 WHERE 设计。
4. ☐ 不在索引列上加函数 / 隐式转换。
5. ☐ 大字段（TEXT / BLOB）独立表，避免回表搬运。
6. ☐ 选合适字段类型：能 INT 不 BIGINT，能 VARCHAR(50) 不 VARCHAR(255)。
7. ☐ 时间字段用 DATETIME / TIMESTAMP（注意 2038）。
8. ☐ 字符集用 `utf8mb4`，避免 `utf8`(MySQL 历史坑)。
9. ☐ 事务尽量短；长事务阻塞 MVCC 清理。
10. ☐ 业务避免分布式事务；用 Outbox / 最终一致。
11. ☐ 分页避免深 OFFSET；用游标 / search_after。
12. ☐ 慢查询日志 + pt-query-digest 周报。
13. ☐ 备份：定期全量 + binlog 增量 + 异地 + 演练恢复。
14. ☐ DDL 用 gh-ost / pt-osc，不锁表。
15. ☐ 监控：QPS / TPS / 慢查 / 复制延迟 / 锁等待 / buffer pool 命中率。
16. ☐ 主从延迟告警；强一致读走主或同步从。
17. ☐ 连接池配置（max / min / idle / 超时）；不要应用直连无池。
18. ☐ Redis 大 key / 热点 key 监控；BigKey 拆分。
19. ☐ 缓存与 DB 一致性方案明确（更新 DB → 删缓存）。
20. ☐ 数据安全：最小权限、脱敏审计、传输加密、定期演练。

## 面试速记

1. **B+ 树**：叶子链表 → 范围扫描 + 磁盘友好。
2. **聚簇索引** = 主键 + 数据；二级索引回表。
3. **覆盖索引**：查询列全命中索引，不回表。
4. **MVCC + 间隙锁** = InnoDB RR 防幻读。
5. **MySQL 默认 RR**，PG / Oracle 默认 RC。
6. **redo（持久性）+ undo（原子性）+ binlog（复制）**；两阶段提交。
7. **缓存三问题**：穿透 / 击穿 / 雪崩。
8. **缓存一致性**：更新 DB → 删 cache（Cache-Aside）。
9. **Snowflake**：1+41+10+12，注意时钟回拨。
10. **utf8mb4** 才是真 UTF-8；emoji 必备。
11. **分页深 OFFSET 慢** → 用主键游标 / search_after。
12. **死锁** = 循环等待，InnoDB 检测后 rollback 一方。

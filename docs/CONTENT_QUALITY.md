# 内容质量规范

本规范用于区分“学习笔记”“人工核查内容”和“实验验证内容”。内容数量不作为质量标准。

## 状态定义

### draft

- 用于记录学习过程和待验证假设。
- 可以使用 AI 辅助整理，但不得把不确定内容写成确定结论。
- 文首应列出主要待办事项或已知限制。

### reviewed

- 至少对照一项官方规范、官方文档或源码。
- 写明适用产品、版本和日期。
- 厂商扩展必须与 DDS/RTPS 标准能力分开描述。
- 数值、阈值和性能数据必须注明来源，或明确标为示例。

### verified

除满足 `reviewed` 外，还必须具备：

- 可运行的最小复现程序。
- 固定的依赖与运行环境。
- 明确的输入、执行命令和预期输出。
- 自动化断言或人工可核对的证据。
- 至少记录一次验证日期。

## 推荐文首格式

```yaml
status: reviewed
last_reviewed: YYYY-MM-DD
applies_to:
  - OMG DDS 1.4
  - RTPS 2.5
tested_with: []
ai_assisted: true
```

`tested_with` 为空表示没有在公开环境完成实验，不得标记为 `verified`。

## 技术写作要求

1. 区分标准、厂商实现、ROS 2 行为和项目经验。
2. 避免“必须”“绝对”“永远”等表述，除非规范明确要求。
3. 配置值和规模阈值必须说明测量环境，不能包装成通用口诀。
4. 性能优化先给测量方法，再给候选方案。
5. 代码片段应尽量进入独立示例文件，并由自动化流程编译或执行。
6. 故障案例必须展示证据链：现象、假设、测量、排除、根因、修复、回归。
7. 无法公开证据时，案例只能作为方法示例，不能声称为可复现结论。

## AI 使用规则

AI 可以用于调整结构和措辞、生成初始示例或测试框架、帮助检索待核对的问题。

AI 不能替代规范与官方文档核对、代码编译和运行、性能测量、真实故障根因判断，以及许可证、保密和安全边界确认。

## 发布检查清单

- [ ] 文首标记内容状态。
- [ ] 写明适用范围和版本。
- [ ] 外部事实有来源。
- [ ] 参数值有测量依据或标为示例。
- [ ] 示例经过编译或运行。
- [ ] 不包含公司、客户或个人敏感信息。
- [ ] 不包含无权重新分发的附件。
- [ ] AI 辅助生成的结论已经人工复核。

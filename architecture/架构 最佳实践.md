# 架构 最佳实践

> 系统架构设计的工程化清单，覆盖原则、流程、扩展性、可靠性、组织协作。

---

## 1. 设计原则

* **SOLID + DRY + KISS + YAGNI + POLA**：一切设计的底层（详见 [设计模式](设计模式.md)）。
* **十二要素应用 12-Factor App**：现代云原生服务标尺。
  1. Codebase 一份代码多份部署
  2. Dependencies 显式声明
  3. Config 走环境变量
  4. Backing services 视为附加资源
  5. Build / release / run 严格分离
  6. Processes 无状态
  7. Port binding 自暴露
  8. Concurrency 进程模型水平扩展
  9. Disposability 快速启停
  10. Dev/prod parity 环境一致
  11. Logs 视为事件流
  12. Admin 一次性任务隔离
* **Conway's Law** 与团队拓扑：架构与组织对齐。
* **风险驱动设计**：先识别核心风险（性能、扩展、安全、合规），再决定结构。

---

## 2. 架构设计流程

1. **需求与约束**：业务目标、QPS、数据量、SLA、合规、成本上限、团队规模。
2. **质量属性**：性能、可用性、可扩展性、安全性、可维护性、成本（"-ility"）。
3. **关键决策**：单体 vs 微服务、同步 vs 异步、一致性级别、存储选型。
4. **C4 模型分层画图**：Context → Container → Component → Code。
5. **ADR（Architecture Decision Record）**：每个重大决策一份文档（决策、备选、后果）。
6. **PoC 与基准**：风险点先做最小验证，跑数字而不是拍脑袋。
7. **演进规划**：Strangler / 阶段切流 / 兼容窗口；不要"重写一切"。

---

## 3. 容量规划与扩展

| 维度 | 做法 |
|------|------|
| **垂直扩展** | 单机更强 CPU/内存；上限明显，先用 |
| **水平扩展** | 加节点；无状态服务首选 |
| **读多写少** | 读副本 + 缓存（Redis / CDN） |
| **写多** | 分片 / 异步队列削峰 |
| **冷热分离** | 热数据内存，冷数据 OSS/对象存储 |
| **预估** | QPS × 平均响应 ≈ 并发；峰值取均值 3~5× |

* **缓存层级**：本地 → 进程内 → Redis → DB；命中率 ≥ 90% 才有意义。
* **缓存三大问题**：穿透（不存在 key）、击穿（热 key 过期）、雪崩（同时过期）。对策：空值缓存、互斥锁/单飞、过期 jitter。

---

## 4. 数据存储选型

| 类型 | 适用 |
|------|------|
| **关系型 RDBMS**（PostgreSQL、MySQL） | 强一致、事务、复杂查询 |
| **KV**（Redis、RocksDB） | 极低延迟、缓存、计数 |
| **文档**（MongoDB、Couchbase） | Schema 灵活、嵌套结构 |
| **列式**（ClickHouse、BigQuery） | OLAP、时序聚合 |
| **图数据库**（Neo4j、NebulaGraph） | 关系网络、推荐 |
| **时序**（InfluxDB、TDengine、TimescaleDB） | 监控、IoT |
| **搜索**（Elasticsearch、OpenSearch） | 全文检索、日志 |
| **对象存储**（S3、OSS） | 海量文件、低成本 |
| **消息队列**（Kafka、Pulsar、RabbitMQ） | 事件流 / 解耦 |

口诀：**不要一招鲜**；OLTP + OLAP + 缓存 + 对象存储常组合使用。

---

## 5. 高可用 HA

* **冗余**：N+1 / N+2；跨机架 / 跨可用区 / 跨地域。
* **自动故障转移**：健康检查 + Leader 选举（etcd/ZK）。
* **限流 / 熔断 / 降级 / 舱壁** 四件套防雪崩（见 [微服务架构](微服务架构.md)）。
* **优雅启停**：监听 SIGTERM；K8s `preStop` hook + readiness 摘流。
* **数据备份 + 异地容灾**：明确 **RPO**（数据丢失上限）、**RTO**（恢复时长）。
* **混沌工程**：常态化故障演练；不演练 = 故障即 P0。

---

## 6. 性能与延迟

* **先测量，后优化**：APM + Profiler；不要凭直觉。
* **延迟预算**：从入口到出口逐层分摊；P99 才是用户感知。
* **批处理 + 异步 + 流水线**：榨干吞吐。
* **缓存命中率 / DB 慢查询 / GC pause / 网络抖动** 四大常见瓶颈。
* **Tail at Scale**：长尾治理用 hedged request、超时优化、JVM 调优。

---

## 7. 安全架构

| 层 | 措施 |
|------|------|
| 网络 | VPC + 安全组 + 私网；零信任 + mTLS |
| 接入 | WAF + DDoS 防护 + Bot 识别 |
| 认证授权 | OAuth2/OIDC + RBAC/ABAC；最小权限 |
| 数据 | 静态加密（KMS / TDE）+ 传输加密（TLS） |
| 机密 | Vault / Secret Manager；不入仓 |
| 供应链 | SBOM + 镜像签名（Sigstore）+ CVE 扫描 |
| 审计 | 不可篡改日志 + SIEM |
| 合规 | GDPR / 等保 / ISO 27001 / SOC2 |

---

## 8. 可观测性

* **三大支柱**：Metrics + Logs + Traces；统一 OpenTelemetry 接入。
* **业务指标 + 系统指标 双视角**；核心服务定义 SLI/SLO/Error Budget。
* **告警分级 P0/P1/P2**，避免告警疲劳；自动 runbook 推送。
* **日志规范**：JSON 结构化、trace_id / span_id 透传、敏感脱敏。
* **拓扑图**：服务依赖图随时可看，故障溯源效率 ×10。

---

## 9. CI/CD 与 DevOps

* **一切皆代码**：基础设施（Terraform/Pulumi）、配置（Helm/Kustomize）、流水线（GitHub Actions / GitLab CI）。
* **GitOps**：Argo CD / Flux 拉模式部署，仓库即真相。
* **质量门**：单元测试覆盖 / 静态分析 / SCA / 安全扫描 / 性能基线。
* **发布策略**：蓝绿、金丝雀、渐进交付、Feature Flag。
* **DORA 4 指标**：交付时长、部署频率、变更失败率、恢复时长。

---

## 10. 数据架构

* **OLTP / OLAP 分离**：CDC（Debezium / Canal）→ 数据湖 / 数仓。
* **数据契约 Data Contract**：上游数据变更通知下游消费。
* **Schema 演化**：Protobuf / Avro 向前向后兼容；DB 变更先加后改。
* **数据治理**：Catalog（DataHub / OpenMetadata）+ 血缘 + 质量监控。
* **隐私**：PII 字段标注、按目的最小化收集、可删除（GDPR right to erasure）。

---

## 11. 架构评审 ATAM 简化版

每次重大决策评审清单：

1. **场景**：核心 / 增长 / 异常三类用例分别覆盖。
2. **质量属性优先级**：性能、可用性、扩展性、安全、成本排序。
3. **风险点 R**：列出可能失败之处。
4. **敏感点 S**：哪个组件是质量属性的关键。
5. **权衡点 T**：两个属性矛盾时的选择。
6. **替代方案对比**：至少两套，写明利弊与成本。
7. **演进路径**：未来 1~3 年的扩展通道。

输出：**ADR + 架构图 + 决策日志**。

---

## 12. 反模式 Top 12

1. **大泥球（Big Ball of Mud）**：无清晰边界，模块互相调用。
2. **过度设计**：YAGNI 违反，框架先行需求滞后。
3. **分布式单体**：拆服务但耦合发布。
4. **共享数据库**：多服务读写同一表。
5. **同步链路过深**：A→B→C→D，长尾爆炸。
6. **缺乏监控**：故障靠用户投诉。
7. **没有 SLO**：性能"差不多就行"。
8. **重写诱惑**：抛弃旧系统重写，永远写不完。
9. **银弹崇拜**：迷信新框架/新数据库解决一切。
10. **一致性焦虑**：所有场景都要强一致。
11. **不可演进**：硬编码假设，5 年后无法扩展。
12. **架构脱离组织**：康威定律反噬。

## 13. Top 20 Checklist

1. ☐ 12-Factor 自检通过。
2. ☐ C4 图 + ADR 进仓库。
3. ☐ SLA / SLO / Error Budget 明确。
4. ☐ 关键路径风险 PoC 验证。
5. ☐ 多副本 + 跨可用区部署。
6. ☐ 限流 / 熔断 / 降级 / 舱壁。
7. ☐ 重试幂等 + 退避 + jitter。
8. ☐ 数据备份 + 异地 DR + 定期演练恢复。
9. ☐ 缓存策略明确，命中率监控。
10. ☐ DB 慢查询监控 + 索引审核。
11. ☐ Schema 兼容性入 CI。
12. ☐ 全链路 Trace + 日志关联。
13. ☐ SLO 燃尽率告警。
14. ☐ 安全基线（mTLS / Secret / WAF / SCA）。
15. ☐ GitOps + 蓝绿/金丝雀发布。
16. ☐ Feature Flag 解耦发布与启用。
17. ☐ DORA 4 指标看板。
18. ☐ 故障演练（Chaos）季度化。
19. ☐ 容量规划随业务季度复审。
20. ☐ 成本看板 FinOps（按服务 / 按业务）。

## 面试速记

1. **架构 = 关键决策 + 难以更改的部分**。
2. **质量属性 -ility** 是设计的核心约束（性能、可用性、可扩展、安全、可维护、成本）。
3. **12-Factor App** 是云原生默认起点。
4. **Conway's Law**：组织决定架构。
5. **演进 > 大爆炸重写**：Strangler Fig 套路。
6. **CAP / BASE / 一致性级别** 影响存储选型。
7. **可观测性三件套** + SLO/Error Budget 是现代标配。
8. **DORA 4 指标** 衡量工程效能。
9. **故障是常态**：限流 / 熔断 / 降级 / 舱壁 + 演练。
10. **ADR + C4** 是低成本高价值的架构沟通工具。

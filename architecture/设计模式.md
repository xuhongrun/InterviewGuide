# 设计模式

> GoF 23 模式 + 现代常用模式速查。重点是「**何时用 / 何时不用 / C++ Python 实现要点**」。

---

## 1. 三大类速览

| 类别 | 模式 |
|------|------|
| **创建型 Creational** | 单例、工厂方法、抽象工厂、建造者、原型 |
| **结构型 Structural** | 适配器、桥接、组合、装饰器、外观、享元、代理 |
| **行为型 Behavioral** | 责任链、命令、解释器、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者 |

口诀：**SOLID 原则 + 优先组合而非继承 + 面向接口编程**。

---

## 2. 创建型

### 2.1 Singleton 单例

* **何时用**：全局唯一资源（日志、配置、连接池）。
* **何时不用**：随手当全局变量；可测试性差；多实例需求来时翻车。
* **C++ Meyers Singleton**（线程安全 since C++11）：

```cpp
class Logger {
public:
    static Logger& instance() {
        static Logger inst;   // C++11 起 static 初始化线程安全
        return inst;
    }
    Logger(const Logger&) = delete;
    Logger& operator=(const Logger&) = delete;
private:
    Logger() = default;
};
```

* Python：用模块（天然单例）或 `@functools.cache` 装饰工厂。

### 2.2 Factory Method / Abstract Factory

* 把对象创建从使用方解耦；新增产品族不改调用方。
* C++ 中用 `std::unique_ptr<Base> create(Type t)` 返回多态对象。
* 反模式：**简单 if-else** 已经够用时硬上工厂，过度设计。

### 2.3 Builder 建造者

* 多个可选参数 / 复杂构造步骤 → 链式调用 `obj.with_x().with_y().build()`。
* C++ 替代：**指定初始化器**（C99 / C++20 designated initializers）+ `struct Config{...}`。

### 2.4 Prototype 原型

* 通过克隆现有对象创建新对象，避免昂贵初始化。
* C++：`virtual std::unique_ptr<Base> clone() const = 0;`
* 注意深拷贝 vs 浅拷贝。

## 3. 结构型

### 3.1 Adapter 适配器

* 接口不兼容 → 包一层。典型：把 C 库适配到 C++ 接口。

### 3.2 Bridge 桥接

* 抽象与实现各自独立扩展（如 Shape × Renderer）。
* 反模式：滥用导致类爆炸。

### 3.3 Composite 组合

* 树形结构（文件系统、UI 控件）；叶子和容器同接口。

### 3.4 Decorator 装饰器

* 运行期加功能而不动原类。Python `@decorator` 是语言原生支持。
* C++：`std::function` 包装、模板组合。

```python
def cache(f):
    memo = {}
    def wrap(*a):
        if a not in memo: memo[a] = f(*a)
        return memo[a]
    return wrap

@cache
def fib(n): return n if n<2 else fib(n-1)+fib(n-2)
```

### 3.5 Facade 外观

* 给复杂子系统一个简单门面。典型：SDK 入口类。

### 3.6 Flyweight 享元

* 共享相同状态的对象，节省内存（如字符串 intern、纹理缓存）。

### 3.7 Proxy 代理

* 远程代理（RPC）、虚代理（懒加载）、保护代理（鉴权）。
* 智能指针 `shared_ptr` 是引用计数代理。

## 4. 行为型

### 4.1 Strategy 策略

* 算法可替换；优于 if-else 链。
* C++：`std::function<R(Args...)>` 或模板策略；Python：传函数即可。

### 4.2 Observer 观察者

* 发布订阅；GUI 事件、ROS topic。
* 注意：解注册防悬空；多线程下加锁。
* C++ 现代实现：**信号槽**（boost::signals2、Qt）。

### 4.3 Command 命令

* 把动作封装成对象，支持队列、撤销、重做、日志重放。

### 4.4 State 状态

* 对象行为依状态变化；状态机。
* 实现：状态表 / `std::variant` + visitor / 第三方 boost::sml。

### 4.5 Template Method 模板方法

* 基类骨架，子类填空白；C++ 虚函数 / NVI（Non-Virtual Interface）。

### 4.6 Chain of Responsibility 责任链

* 请求沿链传递，谁能处理谁处理；中间件 / 拦截器是经典实现。

### 4.7 Visitor 访问者

* 在不修改类结构的前提下加新操作；适合 AST。
* C++17 起：`std::visit` + `std::variant` 是更现代的访问者。

### 4.8 Iterator 迭代器

* C++ STL / Python `__iter__` 都是原生支持，无需手写模式。

### 4.9 Mediator 中介者

* 多对多变多对一，避免组件相互依赖；UI 表单、聊天室。

### 4.10 Memento 备忘录

* 保存恢复对象内部状态，支持撤销。

## 5. 现代常用（非 GoF）

| 模式 | 说明 |
|------|------|
| **DI / IoC** | 依赖注入；C++ 用构造注入；框架 Spring / Guice / DryIoc |
| **CRTP** | C++ 静多态，编译期注入子类行为 |
| **PIMPL** | 头文件解耦实现，编译时间与 ABI 友好 |
| **RAII** | C++ 资源管理核心 |
| **Type Erasure** | `std::function` / `std::any` 隐藏具体类型 |
| **Reactor / Proactor** | 高并发 IO（见 [IO 多路复用](../network/IO%20多路复用.md)） |
| **Pub/Sub** | 消息总线，DDS / Kafka |
| **Event Sourcing + CQRS** | 事件存储 + 读写分离 |
| **Saga / Outbox** | 分布式事务 |
| **Repository / Unit of Work** | DDD 领域持久化抽象 |
| **Specification** | 业务规则可组合（`a.and(b)`） |

## 6. SOLID 原则

| 字母 | 名称 | 一句话 |
|------|------|------|
| **S** | Single Responsibility | 一个类一个变化原因 |
| **O** | Open/Closed | 对扩展开放、对修改封闭 |
| **L** | Liskov Substitution | 子类可替换父类不破坏行为 |
| **I** | Interface Segregation | 多个小接口胜过一个胖接口 |
| **D** | Dependency Inversion | 依赖抽象不依赖实现 |

补充：

* **DRY**（Don't Repeat Yourself）
* **KISS**（Keep It Simple, Stupid）
* **YAGNI**（You Ain't Gonna Need It）—— 不要为想象中的需求设计
* **POLA**（Principle of Least Astonishment）—— 最小惊讶

## 7. 反模式 Top 10

1. **单例滥用**：到处全局状态，可测试性归零。
2. **God Object**：一个类几千行什么都干。
3. **过度工厂**：本来 `new T` 一行能搞定。
4. **复制粘贴继承**：违反 LSP，子类破坏父类契约。
5. **接口爆炸**：模式套模式，5 层抽象一个 if-else。
6. **回字四种写法**：同项目模式风格不一致。
7. **设计先行无需求**：YAGNI 违反。
8. **实现细节泄露**：抽象层暴露底层枚举/字段。
9. **状态机失控**：状态转换 if-else 嵌套 5 层。
10. **观察者循环**：A 通知 B，B 反向通知 A，无限递归。

---

## 8. 现代 C++ 中的"消失模式"

得益于语言/库进步，以下经典模式无需手写：

| 模式 | 替代 |
|------|------|
| Iterator | STL iterators / ranges |
| Strategy | `std::function` / lambda |
| Singleton | Meyers static 局部 + DI |
| Visitor | `std::visit` + `std::variant` |
| Prototype | 拷贝构造 / `clone()` 模板 |
| Decorator | 函数组合 / 高阶函数 |
| Template Method | 虚函数 / CRTP |

---

## 9. Top 12 Checklist

1. ☐ 命名清晰、单一职责优先。
2. ☐ 优先组合 > 继承。
3. ☐ 面向接口编程，便于替换 / 测试。
4. ☐ 不预测未来需求（YAGNI）。
5. ☐ 重复 3 次再抽象（Rule of Three）。
6. ☐ 模式落地前先问"不用模式怎样？"。
7. ☐ 代码可测：依赖注入、避免静态全局。
8. ☐ 状态机 ≥ 5 状态用 FSM 库或表驱动。
9. ☐ 异常 / 错误码风格全项目统一。
10. ☐ 文档说明使用了哪种模式与原因。
11. ☐ 重构前补测试，再小步替换。
12. ☐ Code Review 关注职责而非语法。

## 面试速记

1. **GoF 23 = 创建 5 + 结构 7 + 行为 11**。
2. **SOLID** 是设计原则，不是模式。
3. **优先组合 > 继承**：减少耦合。
4. **依赖倒置**：高层模块不依赖低层，都依赖抽象。
5. **单例线程安全**：C++11 函数内 static / Python 模块即单例 / Java DCL + volatile。
6. **观察者** = Pub/Sub 雏形；ROS topic 是工程化版本。
7. **策略 = if-else 升级**；用 `std::function` / lambda 实现。
8. **状态模式** 替代 switch：每个状态一个对象。
9. **C++17 std::variant + std::visit** 是现代访问者。
10. **YAGNI/KISS/DRY** 比模式更重要 —— 模式不是目的，可读可改才是。
